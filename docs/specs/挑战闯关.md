### 已核验的资料事实与限制

- 仓库 README 描述六艺、每艺十式、阶段记录；不是对仓库动作数据准确性的确认。
- 出版方系列说明支持“十步渐进、最终为 Master Step”。
- 原书搜索返回示例：墙壁俯卧撑进阶为 3 组×50 次；单臂俯卧撑最终技入门为每侧 1 组×5 次、精英为每侧 1 组×100 次；桥最终技进阶表给出 2 组×10–30 次的范围。
- 这些示例证明标准模型必须允许侧别、不同阶段和范围。不能把所有最终技统一设置成同一个组次数值。
- 2026-11-06 已完成 60/60 式目标表格逐项视觉核验，完整数值、单位、侧别及 PDF 页序见 `docs/context/囚徒健身60关标准核验.md`；此前全量阅读限制已解除。采用原书，二手资料仅作差异对照。

- 单臂倒立撑已核验为原书靠墙版本，允许腿部助力；界面需明确动作定义，不能误标为自由倒立或严格无借力版本。
- 桥十式全部按动态次数计；上行桥为下行再上行的完整循环，最终式为站立下桥再直接起身的完整循环。只有倒立撑前三式使用连续保持秒数。

### 推荐业务规则（待 Plan 固化）

1. 六条独立路线，每条十关；各路线第一关初始可挑战，其余可查看，依次解锁。
2. 每关展示入门、中级、进阶/精英目标；前九关以进阶标准通关。第十式达到入门标准即获得最终技成就并计入路线完成；精英标准独立展示，达标后另获精英成就，不阻塞路线完成。最终技口径已获用户确认（2026-11-06）。
3. 挑战成绩按一次挑战的逐组数组保存，重复挑战保留历史；不累计多天或多次成绩凑组数。
4. 单侧动作分别录入左右侧，每侧每组均需达标；不能把左右侧合计当作单侧。
5. 静态保持按单次连续秒数，不能将多次中断时长相加；输入严格拒绝负数、非有限值、次数小数和缺项。
6. 动作要点由用户确认；数量达标且确认动作质量，才通过。明确为自报成绩。
7. 不足目标可保存未通过的尝试，并展示具体差距。通关展示时间和解锁结果。
8. 进度应由有效成绩推导；撤销通关后，受前置约束的后续关卡重新计算，历史尝试保留，避免界面和数据不一致。
9. 动作目录采用稳定 ID、来源和标准版本；成绩保存适用标准快照，便于日后纠错，不在更新资料时静默重写历史。
10. 挑战成绩本地存储、JSON 备份与可选云同步并存；云端使用独立成绩表，不改变训练记录结构。可为当前关生成训练计划，但不据训练计时自动通关。

### 拟定验收标准

- 六艺共 60 关全部有明确、可计算且可追溯的目标；没有未核验数值作为正式关卡条件。
- 逐组不足、缺少一侧、跨次累计、保持中断、未确认质量均不能通关；严格达标可通关。
- 单路线顺序解锁，路线之间独立；第十式入门达标即获得最终技成就并计入路线完成；未达精英标准时仍保留最终技成就，精英标准及达成状态独立展示。
- 刷新和页面切换不丢失进度；JSON 导出导入可还原；旧数据加载不报错；云端下载不丢失本地挑战。
- 挑战页明确数据保存在当前浏览器；设置页可选择上传或下载挑战成绩，取消选择时保留本地挑战字段。
- 移动端可访问关卡、目标与输入，键盘可操作，有标签及明确的锁定/未通过反馈。

### 4.2 Signatures / 数据契约

- `challengeRoutes: Array<{ id, name, subtitle, icon, levels }>`；关卡包含 `id, step, name, englishName, mode, unilateral, standards, tip, sourcePage, version`。
- `challengeDefaults(): { version: 1, attempts: [] }`。
- `normalizeChallenges(value, { strict = false } = {}): ChallengeState`：旧数据缺字段返回默认；严格导入遇到损坏成绩拒绝整次导入，避免静默丢失；未知版本保留为不参与进度的历史成绩。
- `createAttempt(level, stage, rows, qualityConfirmed, note = ''): Attempt`：校验实际成绩；保存 ID、时间、关卡 ID、所选阶段、逐组成绩、质量确认、备注及标准快照。
- `evaluateAttempt(level, attempt, stage): { valid, passed, messages }`：非有限、负数、小数、空字段及缺一侧不能通过；逐组比较，不把总数相加；缺组可显示具体差距；质量确认必须为 true。
- `getRouteProgress(route, attempts): Array<{ level, unlocked, completed, achieved, completedAt }>`：每关仅在所有前置关通过时解锁；第十关以 beginner 判定，精英独立；不同路线互不影响。
- `appendAttempt(state, attempt): ChallengeState`：统一执行前置解锁校验，禁止绕过 UI 写入锁定关卡。
- `removeAttempt(state, attemptId): ChallengeState`：删除指定成绩后重新派生所有进度；后续成绩保留，但前置未通过期间不计通关，恢复前置后可重新生效。

成绩通过标记不落盘，以真实数值与版本快照重新判定。输入采用整数次数/秒数，零可保存为未达标尝试。每次最多三组，单侧每组左右分开；多个尝试不能拼接。新成绩不预填目标值。切换目标阶段可增加需要的组，保留现有已输入值；可增减实际组数。第十关三档目标可独立达成，不要求一组高次数先通过两组的中级档。

桥精英按原文范围下限每组 10 次、共 2 组授予成就，同时显示 2×10–30 及上限目标；通关仍只需入门 1×1。

不增加训练计划生成，不变更训练计时或已有训练记录；新增独立挑战同步表及设置项。界面明确本地保存、可同步远端及自报成绩。录入只保存已提交成绩；切换关卡或离开页面前，对未提交的填写提供丢弃确认。已提交成绩可刷新恢复。
